# M3 — 수익화 · KPI 대시보드 설계 메모

## 1. 수익화 구조 (합법·지속가능, 루트박스/가챠 금지)

| 레이어 | 내용 | 거부감 | 구현 |
|---|---|---|---|
| **F2P 기본** | 하루 무료 라운드 N회(기본 5) | 0 | `src/lib/session.js` 일일 카운트 |
| **보상형 광고** | 힌트 / 추가 라운드 / 재도전 | 최저 | `src/lib/monetization.js#watchRewardedAd()` 스텁 |
| **IAP** | 시나리오·캐릭터 팩 / 무제한 모드 / 광고 제거 | 중 | `monetization.js#purchase()` (Stripe 테스트 모드 자리) |
| **시즌패스** | 코스메틱 페르소나·뱃지 (Pay-to-win 금지) | 중 | `monetization.js#SEASON_PASS` |

**투명성 원칙**: 모든 가격·확률(확률형 없음) 명시. 무제한/광고제거는 일회성. 시즌패스는 코스메틱 전용.

## 2. 단가(COGS) — 라운드당 토큰 경제
가정: 시스템 프롬프트 ~700토큰(캐싱), 턴당 히스토리 누적, 평균 4턴, 턴당 출력 ~180토큰.

| 모델 | 입력 $/1M | 출력 $/1M | 라운드 추정* | 비고 |
|---|---|---|---|---|
| `claude-opus-4-8` (기본) | $5.00 | $25.00 | ~$0.03~0.05 | 최고 품질, 캐싱 적용 |
| `claude-haiku-4-5` (옵션) | $1.00 | $5.00 | ~$0.006~0.01 | 프로덕션 비용 최적, `MODEL` env로 교체 |

\* 캐싱(cache_read ~0.1×)·턴수에 따라 변동. 실측으로 재보정(`messages.count_tokens`).

**비용 통제 레버**: ①프롬프트 캐싱 ②히스토리 6턴 상한 ③`max_tokens` 캡(256) ④무료횟수 제한 ⑤모델 env 교체.
> 권고: 트래픽 확장 시 `MODEL=claude-haiku-4-5`로 전환해 COGS 5~7배 절감 검토. (기본값은 품질 우선 opus 유지)

## 3. KPI 대시보드 설계 (이벤트 → 지표)
분석 훅: `src/lib/analytics.js#track(event, props)` → `window.dataLayer` + (옵션)`/api` 전송 지점.

| 이벤트 | 트리거 | 산출 지표 |
|---|---|---|
| `round_start` | 라운드 시작 | DAU, 세션당 라운드수 |
| `round_complete` | 성공/실패 확정 | 성공률, 난도 밸런스 |
| `share_click` | 공유 버튼 | **공유 전환율** = share/round |
| `challenge_open` | 챌린지 링크 진입 | 바이럴 계수(K) |
| `ad_view` / `ad_complete` | 보상형 광고 | **광고 시청률**, eCPM×시청 = 광고매출 |
| `paywall_view` / `iap_click` / `iap_success` | 페이월·결제 | 전환율, **ARPDAU** |
| `retain_d1` / `retain_d7` | 재방문(세션 날짜) | **D1/D7 리텐션** |

**대시보드 4분면**: (1)획득=공유전환·K · (2)인게이지=라운드/세션·성공률 · (3)리텐션=D1/D7 · (4)매출=ARPDAU·광고시청·IAP전환.

## 4. 바이럴/성장 루프
- 결과 → OG 이미지/카드 자동 생성(`/api/og`) → 원탭 공유
- "이 캐릭터 너도 뚫어봐" 챌린지 링크(scenario seed 포함) + 일일 리더보드
- 공유 시 보너스 라운드 → 공유가 곧 UA

## 5. 현실 점검
인디 게임 대다수는 수익 미미·시장 집중이 심함. 본 산출물은 **보장된 수익이 아니라 빠르게 검증할 MVP**.
위 검증지표를 먼저 띄우고, 공유전환·D1이 목표를 넘는지로 확장 여부를 데이터로 결정한다.
